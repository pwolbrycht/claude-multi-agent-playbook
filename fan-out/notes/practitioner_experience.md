# Practitioner experience with multi-agent fan-outs in Claude Code and similar frameworks

Researched 2026-10-28. Scope: what developers, bloggers, HN/GitHub commenters and framework authors report about orchestrator stalls and which fan-out designs work. Each finding is tagged **[measured]** (a number someone actually counted), **[anecdote]** (a single practitioner's report), **[official]** (vendor docs or engineering blog) or **[opinion]**. Reddit r/ClaudeAI and r/ClaudeCode could not be reached directly through the search tool (see Gaps); the equivalent practitioner voice here comes from Hacker News, GitHub issues on anthropics/claude-code, dev.to and Substack.

## Key question 1: Parent-context bloat with many subagents ("context exhausted", "compaction loop", "stalling") and the fixes people adopted

### Takeaway
The consensus mechanism is clear and agreed by official docs and practitioners alike: a subagent's tool calls stay in its own window, but its *final message is pasted verbatim into the parent*, so a fan-out of N verbose workers fills the parent as surely as doing the work inline. The reported stall modes are (1) repeated compaction of a long-running orchestrator that holds every phase's intermediate output ("compaction tax"), (2) runaway spawning (7 to 415 subagents) that exhausts the usage window before any worker finishes, and (3) zombie/looping background subagents that block the parent. The fixes that practitioners converge on are: tell each worker exactly what shape and size to return; push fan-out one nesting level down so intermediates die with the worker; keep a build journal because compaction *will* happen; and cap concurrency.

### Cited Findings
- **[official]** Claude Code docs: a subagent "does that work in its own context and returns only the summary", but "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own while it runs." Docs recommend e.g. "report only the failing tests with their error messages." — [Claude Code docs: Create custom subagents](https://code.claude.com/docs/en/sub-agents)
- **[official]** Same docs, "use the main conversation when": frequent back-and-forth; "Multiple phases share significant context, such as planning, implementation, and testing"; quick targeted change; "Latency matters. A subagent that isn't a fork starts fresh and may need time to gather context." — [Claude Code docs](https://code.claude.com/docs/en/sub-agents)
- **[official]** The parent receives the subagent's final message verbatim as the tool result; "the isolation boundary does not limit the size of the final message. That is controlled by the delegation prompt." Nesting depth is 3 layers by default since 2.1.219 (was 5 in 2.1.172–2.1.216, 1 in 2.1.217–218); `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` disables nesting. "Claude is conservative about parallelism by default", so state the fan-out count explicitly. — [hidekazu-konishi.com subagents and orchestration guide, updated 2026-10-18](https://hidekazu-konishi.com/entry/claude_code_subagents_and_orchestration_guide.html)
- **[anecdote, detailed]** GitHub issue #19077 (opened 2026-01-18): a 9-hour `/goal` session running a 10-phase workflow (PRD, dual review, plan, review-fix loop, orchestrated implementation, testing, ensemble review, fix-and-verify, report) kept every phase's intermediate state in the Opus orchestrator's context, causing "repeated compaction" that "degraded the orchestrator's memory of early decisions." Author names it a "compaction tax" scaling with `session_length × intermediate_output_size`. The prompt itself said: "You WILL get compacted repeatedly as you do all of this. Use a build journal..." Proposed fix: depth-0 holds only phase verdicts, depth-1 holds working state, depth-2 does fan-out so intermediates are discarded with the worker. Maintainer @bcherny closed it 2026-08-19 when 2.1.219 shipped nested subagents (depth 3 default). No token counts given. — [anthropics/claude-code #19077](https://github.com/anthropics/claude-code/issues/19077)
- **[anecdote]** HN, thread "Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k" (approx. July 2026): user *mcv* gave Claude Code a large task; it "immediately launched 7 subagents" which "used up the budget before any of them finished"; retrying 5 hours later gave the same result; the same task run sequentially in the main agent caused "no problem at all." mcv now blocks subagents via CLAUDE.md. Successes were context isolation for doc-heavy lookups and file-based planning (RFC in markdown before coding). — [HN 45181577](https://news.ycombinator.com/item?id=45181577)
- **[anecdote]** HN thread on a hardcoded instruction telling Opus 5 not to use subagents: commenters suggest it was a bug workaround because the model "over-prescribes" subagents. — [HN 49056022](https://news.ycombinator.com/item?id=49056022)

- **[bug report]** Issue #58637: stop hook loops because background subagents still show "running" after they finished (zombie state). - **[official-ish, third-party summary]** Anthropic docs name "Autocompact is thrashing" (a file or tool output refills context right after each summary); remedies: chunk the file, focused `/compact`, delegate to a subagent, or `/clear`. — [ClockedCode guide](https://clockedcode.com/blog/claude-code-stuck-on-compacting)
- **[anecdote, measured-ish]** One guide reports running tasks in the main session used 56% of context versus 18% of the orchestrator's context when the same work went to subagents, and calls `run_in_background: true` "Critical for context optimization." No setup described; treat as a single anecdote. — [dplooy.com Claude Code Tasks guide, 2026-10-28](https://www.dplooy.com/blog/claude-code-tasks-complete-guide-to-ai-agent-workflow)
- **[anecdote]** Rich Snapp (2025-10-05): bloat came from web search/fetch, large docs, MCP services and multi-topic conversations; fix was a `@agent-docs-planner` subagent that does the fetching and returns a summary, full transcript viewable with ctrl-o. No numbers. — [richsnapp.com](https://www.richsnapp.com/article/2025/10-05-context-management-with-subagents-in-claude-code)
- **[official]** Anthropic's own research system: early versions spawned "50 subagents for simple queries"; agents "distracted each other with excessive status updates"; vague task descriptions produced duplicated searches and coverage gaps. — [Anthropic, How we built our multi-agent research system, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system)
- **[bug report]** Issue #59309: CLAUDE.md rules not propagated to subagents and weakened after compaction. — [anthropics/claude-code #59309](https://github.com/anthropics/claude-code/issues/59309)
- **[third-party]** Per-subagent `autoCompactWindow` (100000–1000000) reportedly added in v2.1.296; single blog source, unverified. — [startdebugging.net, Oct 2026](https://startdebugging.net/2026/10/how-to-give-each-claude-code-subagent-its-own-compaction-threshold-with-autocompactwindow/)

### Inferences
- The "stall" people describe is rarely a hard crash. It is either (a) the orchestrator compacting repeatedly and losing early decisions, or (b) the usage window emptying because the fan-out multiplied the per-wall-clock-minute spend. Both are proportional to N × (per-worker startup cost + size of returned result).
- Per-worker startup overhead (reported 10k–30k tokens of system prompt plus re-reading code) is the dominant cost term in small fan-outs, which is why sequential-in-parent sometimes wins outright.
- The maintainers' answer to orchestrator bloat was structural (nested subagents so intermediates die one level down), not a larger window. That matches the #19077 author's own proposed fix and the hierarchical pattern (d).

### Gaps
- No practitioner published a measured curve of orchestrator token count vs. number of subagents, or a "slow after 300k" measurement. The phrase "slow after 300k" did not appear in any source found.
- No Reddit threads could be reached; the r/ClaudeAI and r/ClaudeCode perspective is inferred from HN and GitHub, which skew toward power users.

## Key question 2: The "write to file, return path + short summary" pattern: prevalence, effectiveness, named conventions

### Takeaway
Writing raw output to a file and returning a short summary is widely recommended and widely used, but it is a community convention, not a documented Claude Code feature; the official docs only say "return a summary." It works within a session; its known failure modes are concurrent writers colliding on files, a Write-tool refusal that silently falls back to dumping content into the parent, and files going stale across sessions. The named conventions are `HANDOFF.md`, `memory/handoff-[date].md`, `STATE.md`/`PROJECT.md`/`ROADMAP.md`, a "build journal", manifests with status fields, and Manus's rewritten `todo.md`. I found no source using `progress.md` or "task journal" as a standard name.

### Cited Findings
- **[official]** Anthropic research system: "Subagents can store outputs in external systems and pass lightweight references back to the coordinator. This reduces information loss and token overhead." The lead agent "saves its plan to memory because context beyond 200,000 tokens gets truncated." — [Anthropic multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- **[official]** Claude Platform docs "Build an orchestration mode" example: subagents must call `report_findings` exactly once with a 2–3 sentence `summary` plus structured `findings` (claim, evidence, severity); bash output trimmed to 8,000 chars; results stored in `orchestration_journal.json` keyed by SHA-256 of the prompt, written atomically, so "only the subtasks that never finished are recomputed." `MAX_CONCURRENT` 10, `MAX_TOTAL_SUBTASKS` 200, 15 turns per subagent. — [Claude Platform docs](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-effort-example)
- **[community]** A guide calls a shared scratch file that later subagents read "the cheapest real coordination mechanism"; works within a single session, does not survive it, and "concurrent writes need care." — [vantaige.io, 2026](https://vantaige.io/blog/claude-code-subagents-save-context-3-patterns)
- **[bug report]** Issue #44657: a subagent's Write tool rejected `.md` files named "report"/"summary"/"findings"/"analysis" with no opt-out; the subagent then returned the content as text, "which consumes parent context budget for content that was specifically meant to be persisted to a file." Workaround: put a fallback instruction in the spawn prompt. — [anthropics/claude-code #44657](https://github.com/anthropics/claude-code/issues/44657)
- **[community]** Substack post: each agent "writes results to a markdown file, which the next agent reads", avoiding "the token overhead of passing everything through the main context." — [typhren.substack.com](https://typhren.substack.com/p/sub-agents-in-claude-code-the-subagent)
- **[anecdote]** Show HN "I solved Claude Code's context drift with persistent Markdown files" (~March 2026): `PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md` read before acting; three products in 30 days (13h, 18h, 9h). Commenters asked for benchmarks (none given) and noted multiple agents in one directory still collide; proposed git worktrees. — [HN 47402125](https://news.ycombinator.com/item?id=47402125)
- **[community]** `HANDOFF.md` pattern: "CLAUDE.md describes the project structure and conventions, while HANDOFF.md describes the current state of work." — [fazm.ai](https://fazm.ai/blog/claude-code-architecture-handoff-pattern); the "Handoff Protocol" writes `memory/handoff-[date].md` at session end (done / in progress / blocked / exact next step) and claims context-setting drops from 10–15 min to ~30 s per session (2026-03-19) — [claudecodeguide.dev](https://claudecodeguide.dev/blog/handoff-protocol-saves-10-minutes); GitHub feature request #11455 (2025-11-11) proposes a standard `.claude/handoff.md`, not shipped — [anthropics/claude-code #11455](https://github.com/anthropics/claude-code/issues/11455); Claude-Command-Suite ships a `/handoff` command saving to `docs/handoffs/` as `HANDOFF_[TOPIC]_[TIMESTAMP]` — [qdhenry/Claude-Command-Suite](https://github.com/qdhenry/Claude-Command-Suite/blob/main/.claude/commands/session/handoff.md)
- **[community]** Manifest-driven orchestration: the orchestrator reads a manifest to pick the next item, "Status is tracked in the manifest." — [jeremylongshore ORCHESTRATION-PATTERN.md](https://github.com/jeremylongshore/claude-code-plugins-plus-skills/blob/main/workspace/lab/ORCHESTRATION-PATTERN.md)
- **[official]** Claude Code docs: `memory` directories (user/project/local scope) whose `MEMORY.md` top is injected into the agent's system prompt; subagent transcripts persist independently; `isolation: worktree` gives a subagent its own repo copy. — [hidekazu-konishi guide](https://hidekazu-konishi.com/entry/claude_code_subagents_and_orchestration_guide.html)
- **[vendor blog]** Manus (July 2025): treat the file system as "the ultimate context... unlimited in size, persistent by nature"; compression is only safe if "restorable"; keep a `todo.md` that is rewritten each step so the plan "floats to the end" of context (recitation); keep failed actions visible; cache hit rate is the key production metric; input:output ratio ~100:1. — [Manus, Context Engineering for AI Agents](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- **[anecdote]** Eric Cheng (2025-07-28): keeps "a prompt file that tracks finished files, so a rerun resumes at the first unfinished one" and restarts the refactor every five hours after the limit resets. — [dev.to](https://dev.to/onlineeric/claude-code-sub-agents-burn-out-your-tokens-4cd8)
- **[community]** Anthropic's Ralph Wiggum plugin uses a Stop hook and keeps the same context across iterations ("merely automating the continue button"), the opposite of Huntley's fresh-context loop where "state lives in files, not conversation." — [codecentric](https://codecentric.de/en/knowledge-hub/blog/the-ralph-wiggum-loop-autonomous-code-generation-with-a-fresh-context), [decodingai](https://www.decodingai.com/p/ralph-loops)

### Inferences
- Effectiveness is mostly claimed, not measured; the only hard numbers are the 56%/18% anecdote (Q1) and the handoff-protocol time claim, neither with a described method. The pattern is nonetheless the default recommendation in every orchestration write-up found.
- The pattern's weak point is the fallback path: when the file write fails or the worker ignores the instruction, the full text lands in the parent anyway. Structured return (a tool schema, as in the Platform docs example) is more robust than a prose instruction.

### Gaps
- No source quantifies how often workers ignore "write to file, return summary" instructions.
- "progress.md" and "task journal" as named conventions: not found in any source.

## Key question 3: Usage limits (5-hour window, weekly caps) and parallel-session 429s: slowdown vs. hard cut-off

### Takeaway
Two distinct limits are reported. The 5-hour/weekly *usage* limit is a hard cut-off that fan-outs reach faster because "quota drains proportionally to concurrency" (parallel 15 min vs. sequential 30 min on Pro, measured by one user). Separately, since roughly April–September 2026 Max users report a *server-side concurrency/burst throttle* ("Server is temporarily limiting requests (not your usage limit)") at only 2–6 concurrent sessions or subagents while plan usage reads 20–30%; it manifests as silent retries (slowdown, up to 6–10 attempts) and then hard failure of that agent with lost work. No Anthropic staff response appears on any of these issues; the community workaround is to stagger launches by 2–15 s and retry per-agent with backoff. Claude Code itself caps concurrent subagents at 20 (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`).

### Cited Findings
- **[measured, single user]** Eric Cheng, 2025-07-28: Pro plan hit its usage limit in ~15 minutes with five parallel subagents (Claude Code started them without being asked); the same job sequentially took ~30 minutes; he estimates Max $100 would last ~75 minutes. "Your quota drains proportionally to concurrency." — [dev.to](https://dev.to/onlineeric/claude-code-sub-agents-burn-out-your-tokens-4cd8)
- **[community]** Subagent work "still counts against your plan's 5-hour rolling limit. More speed therefore ⇒ more tokens burned per wall-clock minute." — [mindstudio.ai](https://www.mindstudio.ai/blog/ai-agent-token-budget-management-claude-code); per-subagent startup overhead "10K–20K tokens before any user task is added." — [aicrossroads.substack.com](https://aicrossroads.substack.com/p/claude-code-subagents)
- **[anecdote]** A user hit the weekly limit twice after running eight Claude Code sessions nonstop for a week. — [Jamie Ferguson blog via search](https://www.goodreads.com/author/show/3285253.Jamie_Ferguson/blog)
- **[official]** Anthropic: 5-hour sessions start with the first message; message count varies with length. — [support.anthropic.com](https://support.anthropic.com/en/articles/11014257-about-claude-max-plan-usage); TechRadar: 5-hour limits burn faster during weekday peak hours (5–11am PT), confirmed by a Claude Code engineer on X, weekly limits unchanged. — [TechRadar](https://www.techradar.com/ai-platforms-assistants/claude/claude-is-limiting-usage-more-aggressively-during-peak-hours-heres-what-changed)
- **[community analysis]** Gist claiming the "weekly" cap resets every 72 hours, based on the usage API's rolling counters; not official. — [monperrus gist](https://gist.github.com/monperrus/3ac4b303a84946bbeaf2b1123ee99491)
- **[bug report, measured]** Issue #53922 (opened 2026-04-27, Max 20x and 5x, Linux): ~10 sessions launched back-to-back, first 3–4 work, the rest fail with `API Error: Server is temporarily limiting requests (not your usage limit) · Rate limited`. A May 8 capture: 88 consecutive 429s over ~15 minutes, each request silently retried ~6 times with backoff; `anthropic-ratelimit-*` headers stripped. May 21: failures at 20% session / 30% weekly usage. Workaround: stagger launches 2–5 s; retry individually, never restart the batch. Closed "not planned" by stale bot 2026-07-05; no staff reply. — [anthropics/claude-code #53922](https://github.com/anthropics/claude-code/issues/53922)
- **[bug report]** Issue #60562 (2026-05-19, Max 20x, Opus): "just 2–5 parallel subagents" hit 429s; agents "fail immediately" and "terminate," work lost; no auto-retry; request for per-agent backoff with jitter capped ~60 s. Closed "not planned" 2026-08-31, no staff reply. — [anthropics/claude-code #60562](https://github.com/anthropics/claude-code/issues/60562)
- **[bug report, measured]** Issue #96872 (2026-09-24, Max): 429s concentrated at 6+ concurrent desktop sessions: 14.3% of session-minutes with a 429 at 6+, vs 0–2.2% at 1–5 sessions; retried automatically up to `maxRetries: 10`; 195 rate_limit_error records and 7 turns ending in error on one day; plan usage 27% (5h) / 26% (weekly). Commenter: staggering launches by 10–15 s "dropped the failure rate significantly." No staff reply. — [anthropics/claude-code #96872](https://github.com/anthropics/claude-code/issues/96872)
- **[bug report]** Issue #46037: 429 with multiple parallel sessions below usage cap. — [anthropics/claude-code #46037](https://github.com/anthropics/claude-code/issues/46037)
- **[official]** Claude Code: when 20 subagents are running, spawning another fails with `Concurrent subagent limit reached` and Claude is told not to retry; override with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`; ultracode sessions exempt; "no limit on the total number of subagents Claude can spawn over a session." — [Claude Code docs](https://code.claude.com/docs/en/sub-agents)
- **[official]** Anthropic: agents use ~4× the tokens of chat, multi-agent systems ~15×; on BrowseComp, token usage explained 80% of performance variance. — [Anthropic multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- **[anecdote]** Brandon Redmond: 10 agents cost ~$50/day API + ~$20/day infra; 12 agents overnight produced a 10,000+ line PR; commenter-reported outcomes ~70% clean, ~25% one coordinator retry, ~5% human review. — [dev.to, 2025-08-02](https://dev.to/bredmond1019/multi-agent-orchestration-running-10-claude-instances-in-parallel-part-3-29da)

### Inferences
- "Slowdown vs. hard cut-off" has a layered answer: the concurrency throttle first shows as a slowdown (silent retries) and then as a per-agent hard failure; the usage limit is a hard stop for the whole account. A fan-out that survives the throttle still drains the usage window N times faster.
- The practical ceiling reported by Max users in 2026 is single-digit concurrent streams per account (first 3–4 work; 6+ reliably throttled), well below Claude Code's own cap of 20. Batching into waves of ~3–5 with staggered starts is the only pattern reported to work.

### Gaps
- No official statement from Anthropic on per-plan concurrent-stream limits; all mechanism claims are community hypotheses.
- No source separates subagent-caused usage burn from plain long-session burn with controlled measurement.

## Key question 4: Critiques of multi-agent (Cognition) vs. the counter-argument (Anthropic), and when single-agent with good context management wins

### Takeaway
Cognition (2025-06-12) argues parallel subagents fail because they make conflicting implicit decisions without shared context, and recommends a single-threaded agent plus a fine-tuned compressor. Anthropic (2025-06-13) reports a lead/subagent system beating single Opus 4 by 90.2% on research, at ~15× chat token cost. Harrison Chase's reconciliation (2025-06-16) is the position most practitioners now cite: multi-agent is for breadth-first, read-heavy, parallelizable work whose value justifies the cost; single-agent for write-heavy, dependency-laden work like most coding. HN practitioners broadly agree: subagents for research and context quarantine, not for implementation.

### Cited Findings
- **[opinion, vendor]** Cognition, Walden Yan, 2025-06-12: two principles, "Share context" (full agent traces, not just messages) and "Actions carry implicit decisions"; Flappy Bird example where two parallel subagents produce mismatched art; recommends single-threaded linear agent, with a compression model ("hard to get right"; Cognition fine-tuned smaller models) for long runs; notes Claude Code's subagents (June 2025) run narrow questions and keep investigation out of the main context; names Swarm and AutoGen as promoting the wrong patterns; expects the position to change as models improve. — [cognition.com](https://cognition.com/blog/dont-build-multi-agents)
- **[official, measured]** Anthropic, 2025-06-13: Opus 4 lead + Sonnet 4 subagents beat single Opus 4 by 90.2% on internal research eval; subagents return "a condensed result"; effort scaling rules: 1 agent/3–10 calls for facts, 2–4 subagents/10–15 calls for comparisons, 10+ for complex research; a single agent writes the final report. — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)
- **[opinion]** Harrison Chase, 2025-06-16: the two posts agree that context engineering is critical and that "read" systems are easier than "write" systems; "Conflicting writes are costlier than conflicting reads"; multi-agent fits breadth-first tasks, work exceeding one window, many complex tools; fits poorly when agents must share context or have many dependencies, "as most coding tasks do." — [langchain.com](https://www.langchain.com/blog/how-and-when-to-build-multi-agent-systems)
- **[opinion]** Cosine: Cognition's position "isn't principled—it's status quo bias." — [cosine.sh](https://cosine.sh/blog/why-you-should-build-multi-agent-ai)
- **[opinion]** Pat McGuinness: the two sides agree more than their titles suggest; multi-agent burns ~15× tokens. — [patmcguinness.substack.com](https://patmcguinness.substack.com/p/the-ai-agent-architecture-debate)
- **[opinion]** Simon Willison frames subagents as "context quarantine", the pattern used by Claude Code and explored in Anthropic's research paper; notes you can trigger them "just by telling it to do so." — [simonwillison.net, 2025-10-11](https://simonwillison.net/2025/Oct/11/sub-agents)
- **[anecdote]** HN: "the latest frontier models are very good at taking the knowledge they've acquired during a session and applying it forward," weakening the case for subagents; others: subagents "more suitable for research tasks to provide informed context to the parent agent." — [HN 45181577](https://news.ycombinator.com/item?id=45181577), [HN 48884047](https://news.ycombinator.com/item?id=48884047)
- **[anecdote]** A practitioner who tried multi-agent orchestration "collapsed the system into two agents: a writer and a reviewer operating in a loop. The simpler version performed better." — [decodingai.com](https://www.decodingai.com/p/ralph-loops)
- **[opinion]** channel.tel: the single-agent problem "is less about the 200k-token limit and more about attention diluting across many rule sets"; scoping subagents to relevant rules helped. — [channel.tel](https://www.channel.tel/blog/claude-code-subagents-orchestrator-pattern)

### Inferences
- The disagreement is narrower than the headlines: both camps agree the coordinator must see condensed, not raw, worker output, and that write-phase work should be done by one context. Anthropic's "single agent writes the final report" and Cognition's "compressor" are two ways to keep one coherent decision-maker.
- Cognition's critique applies directly to fan-outs of *implementers* (pattern e with fresh briefs is exactly what they warn about); it applies much less to fan-outs of *readers/researchers* returning summaries.

### Gaps
- No direct reply from Cognition to Anthropic or vice versa was found; the "response" framing is commentators' interpretation.

## Key question 5: Patterns from adjacent frameworks (LangGraph Send, OpenAI handoffs, Manus, Breunig, Martin) and what they recommend for orchestrator context

### Takeaway
Every adjacent framework converges on the same shape: fan-out decided by a routing function or code, workers returning small structured results that a reducer appends to shared state, and the orchestrator holding only the reduced state. Breunig and Martin give the vocabulary (quarantine/isolate, offload/write, compress, select) and the supporting numbers; Manus adds the production metric (KV-cache hit rate) and the file-system-as-memory rule.

### Cited Findings
- **[framework docs]** LangGraph map-reduce: a routing function returns one `Send` per item (that function "IS the map step"); a reducer such as `operator.add` on a shared state key appends each worker's result instead of overwriting; the orchestrator-worker variant decides subtasks at runtime; summarization is map per chunk then reduce to a global summary. — [LangChain summarize map-reduce](https://python.langchain.com/docs/how_to/summarize_map_reduce), [netjstech orchestrator-worker](https://www.netjstech.com/2026/06/orchestrator-worker-workflow-in-langgraph.html)
- **[framework docs]** OpenAI Agents SDK: on a handoff "the receiving agent takes over the conversation and sees the entire previous history" unless an `input_filter` trims it (e.g. `remove_all_tools`); nested handoff history (opt-in beta) condenses prior history into summary segments; `Agent.as_tool(...)` is the way to call a specialist "without transferring the conversation" (orchestrator keeps control). — [openai.github.io handoffs](https://openai.github.io/openai-agents-python/handoffs/)
- **[blog]** Lance Martin (2025-06-23): four buckets, write (scratchpads, memory), select, compress, isolate; sub-agent isolation "one of the most popular" methods; costs are higher token use, careful planning prompts, and coordination; Cognition uses summarization at agent-to-agent handoffs with a fine-tuned model. — [rlancemartin.github.io](https://rlancemartin.github.io/2025/06/23/context_engineering/)
- **[blog]** Drew Breunig (2025-06-26): failure modes poisoning, distraction (Gemini Pokémon agent degraded beyond ~100k tokens), confusion (Llama 3.1 8b failed with 46 tools, passed with 19), clash; tactics: tool loadout (DeepSeek-v3 selection critical above 30 tools, near-certain failure beyond 100), context quarantine (isolate parallelizable breadth-first subtasks; "Avoid this pattern when tasks need heavy shared context"), pruning, summarization as its own evaluated stage, offloading to a "scratchpad" (think tool +54% on a specialized benchmark). "Context is not free." — [dbreunig.com](https://www.dbreunig.com/2025/06/26/how-to-fix-your-context.html)
- **[vendor blog]** Manus: rebuilt the framework four times; file system as external memory; restorable compression; recitation via `todo.md`; keep errors in context; vary serialization to avoid mimicry; mask tools rather than remove them. — [manus.im](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- **[official]** Claude Platform "orchestration mode" example: code (ThreadPoolExecutor, `MAX_CONCURRENT=10`) does the fan-out; a second adversarial-verifier wave per result; journal for resumability; docs warn fan-out "multiplies token usage" and a few-hundred-line module "rarely needs more than about ten subtasks." — [platform.claude.com](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-effort-example)
- **[blog]** Ken Huang on Claude Code Dynamic Workflows (research preview 2026-05-28): "a generated JavaScript script IS the orchestrator"; only the verified final answer reaches Claude's context; up to 1,000 agents per run, 16 concurrent. — [kenhuangus.substack.com](https://kenhuangus.substack.com/p/claude-code-orchestration-dynamic)

### Inferences
- Pattern (b), deterministic code doing fan-out and merge, is now Anthropic's own documented recommendation (orchestration-mode example, Dynamic Workflows), which is the strongest endorsement any of the six patterns has.
- OpenAI's default handoff (full history transfer) is the anti-pattern Cognition and Breunig warn about for context size; the `as_tool` and `input_filter` mechanisms exist precisely to make the orchestrator see less.

### Gaps
- No CrewAI or AutoGen practitioner reports on orchestrator stalls were found in this pass; only Cognition's mention of AutoGen as promoting the wrong patterns.

## Key question 6: Open-source Claude Code orchestration setups and what their authors learned about keeping the coordinator thin

### Takeaway
The setups with the clearest lessons are the Ralph-loop family (fresh context each iteration, state in files and git, objective exit gate) and script-driven pipelines (one deterministic script feeds atomic steps to fresh agents and commits each). claude-flow/Ruflo makes large architectural claims (queen-led hierarchy, vector memory, 100+ agents) but its README contains no measurement of coordinator-context savings and carries many self-stated caveats. BMAD users report the spec files themselves become the context burden.

### Cited Findings
- **[community]** Ralph Wiggum loop (Geoffrey Huntley, 2025-07-14): a bash `while` loop re-feeding a prompt until criteria are met; each run reads plan and progress log from disk; "sidesteps context rot entirely when the spec and plan serve as the source of truth"; "the reason the technique works, and... the reason it is expensive." — [codecentric](https://codecentric.de/en/knowledge-hub/blog/the-ralph-wiggum-loop-autonomous-code-generation-with-a-fresh-context), [futureagi](https://futureagi.com/blog/loop-engineering/ralph-loop/)
- **[anecdote]** Amplitude, Eric Carlson, 2026-05-13: one-week Ralph loop with browser verification shipped 102 features; lesson: "The dispatcher and verification gate matter more than the loop itself"; a loop without objective definitions "just burns tokens"; no cost or token numbers. — [amplitude.com](https://amplitude.com/blog/ralph-loop)
- **[community]** Sessions that don't log incrementally lose all progress on context overflow; log partial progress so the next session resumes from a checkpoint. — [decodingai](https://www.decodingai.com/p/ralph-loops)
- **[anecdote]** HN: a user split a plan into atomic steps and ran "a deterministic script that passed each step to a fresh agent and committed after each one," waking up to "a long list of commits." — [HN 45181577](https://news.ycombinator.com/item?id=45181577)
- **[community]** Redmond's 10+ instance system: meta-agent decomposes tasks into a Redis queue; worker subprocesses with per-file Redis locks (5-min expiry) and Docker CPU/memory limits; commenters add worktree-per-agent and "a deterministic coordinator, not an AI agent" for merges; context drift raised by a commenter, fix: snapshot repo state at spawn and reconcile diffs at the coordinator. — [dev.to](https://dev.to/bredmond1019/multi-agent-orchestration-running-10-claude-instances-in-parallel-part-3-29da)
- **[README, self-reported]** claude-flow (now "Ruflo"): "Queen-led hierarchy (Raft, Byzantine, Gossip)", HNSW AgentDB memory, 100+ agents, 314 MCP tools, 27 hooks; benchmarks vs LangGraph/AutoGen/CrewAI "1.3×–1953×" from a gist; README states the architecture flow is "a conceptual flow, not a live execution trace," demos use sample data, and creating a mission "does not mean the feature has been implemented"; 660 open issues; no token-reduction claim found. — [github.com/ruvnet/claude-flow](https://github.com/ruvnet/claude-flow)
- **[anecdote]** BMAD + Claude Code: specs, architecture docs and story files "consume context quickly on larger projects," forcing a detail-vs-brevity trade-off. — [dev.to bspann](https://dev.to/bspann/bmad-method-claude-code-how-i-actually-ship-projects-with-spec-driven-ai-development-1eei)
- **[community]** Multi-day work should use "subagents with explicit state (task descriptions, not in-memory coordination)." — [mindstudio.ai](https://www.mindstudio.ai/blog/sub-agents-claude-code-context-management)
- **[official]** Claude Code: for work that won't fit one window, docs point to separate sessions with cross-session messaging rather than deeper subagent trees. — [Claude Code docs](https://code.claude.com/docs/en/sub-agents)

### Inferences
- The projects whose authors report concrete lessons all moved coordination *out of* the LLM (shell loop, script, Redis queue, git) and left the LLM only the per-step work. The projects that keep an LLM "queen" coordinating report feature counts, not context or stall measurements.
- "Keep the coordinator thin" in practice means: the coordinator holds a manifest/journal and verdicts, never worker transcripts; the merge is done by code or by one fresh agent reading files.

## Key question 7: Pattern-by-pattern verdict (a)–(f) from the evidence above

### Takeaway
(a) summaries-only-to-orchestrator and (b) code-driven fan-out/merge have the strongest support, including Anthropic's own docs; (c) capping/batching is forced by the 2026 concurrency throttle regardless of design; (d) hierarchical map-reduce is what the maintainers shipped (nesting depth 3) in answer to the compaction-tax issue; (e) fresh agents with written briefs beat forks for cost but are exactly where Cognition's "conflicting implicit decisions" bites, so use them for readers, not writers; (f) short-lived orchestrators with file handoff is the Ralph/handoff.md consensus, with the caveat that it is expensive per iteration and unmeasured beyond anecdotes.

### Cited Findings
- (a) Official warning that detailed returns "can consume significant context" and the "report only the failing tests" advice — [Claude Code docs](https://code.claude.com/docs/en/sub-agents); Anthropic subagents return "a condensed result" and pass "lightweight references" — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system).
- (b) Platform docs orchestration example with code fan-out, journal and structured `report_findings` — [platform.claude.com](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-effort-example); Dynamic Workflows where "a generated JavaScript script IS the orchestrator" — [kenhuangus.substack.com](https://kenhuangus.substack.com/p/claude-code-orchestration-dynamic); HN deterministic step script — [HN 45181577](https://news.ycombinator.com/item?id=45181577).
- (c) 429s at 2–6 concurrent streams on Max while usage is 20–30%; stagger 2–15 s; retry per agent — [#53922](https://github.com/anthropics/claude-code/issues/53922), [#60562](https://github.com/anthropics/claude-code/issues/60562), [#96872](https://github.com/anthropics/claude-code/issues/96872); built-in cap of 20 — [Claude Code docs](https://code.claude.com/docs/en/sub-agents); Anthropic's 2–4 / 10+ subagent scaling rules — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system).
- (d) #19077's depth-0 verdicts / depth-1 state / depth-2 fan-out proposal and the 2.1.219 nesting change — [#19077](https://github.com/anthropics/claude-code/issues/19077); LangGraph map then reduce — [LangChain](https://python.langchain.com/docs/how_to/summarize_map_reduce).
- (e) Fresh subagents start without conversation history and need the brief to carry everything; forks inherit it — [Claude Code docs](https://code.claude.com/docs/en/sub-agents); vague briefs cause duplicated searches — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); "actions carry implicit decisions" — [Cognition](https://cognition.com/blog/dont-build-multi-agents); per-fresh-agent overhead 10–30k tokens — [HN 48883796](https://news.ycombinator.com/item?id=48883796), [aicrossroads](https://aicrossroads.substack.com/p/claude-code-subagents).
- (f) Ralph loop fresh context per iteration with state in files — [codecentric](https://codecentric.de/en/knowledge-hub/blog/the-ralph-wiggum-loop-autonomous-code-generation-with-a-fresh-context); HANDOFF.md / `memory/handoff-[date].md` — [fazm.ai](https://fazm.ai/blog/claude-code-architecture-handoff-pattern), [claudecodeguide.dev](https://claudecodeguide.dev/blog/handoff-protocol-saves-10-minutes); Anthropic: "spawn fresh subagents with clean contexts and hand off their work" when limits approach — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system).

### Inferences
- The combination practitioners describe as working is (b)+(a)+(c)+(f): a script or thin loop fans out in waves of 3–5 fresh workers with explicit briefs, each writing to a file and returning a structured stub, a journal/manifest tracks completion, and the merge is either code or a single fresh agent reading the files. (d) is how you extend that when a wave's stubs are still too big for the parent.
- For a Max 5x account where the 5-hour window is the binding limit and fan-outs were capped by total agent count (~40): the throttle data says ~40 agents is far above the 3–6 concurrent streams Max users report surviving in 2026, so the number that matters is *concurrent* streams per wave, not total agents per workflow.
