# Claude Code mechanics that make a subagent fan-out stall (CLI and desktop app)

Researched 2026-10-28. "Documented" = Anthropic docs (code.claude.com, platform.claude.com, support.claude.com), read on 2026-10-28; the docs pages carry no visible "last updated" date but cite Claude Code versions up to v2.1.311, so they are current. "Reported" = GitHub issues on anthropics/claude-code (dates and status given) or third-party write-ups. Where I only saw a search snippet and not the full page, I say so.

## Q1. Subagents (Agent tool): what returns to the parent, size limits, background vs foreground, forks

### Takeaway
Documented: only the subagent's final result returns; its tool calls and tool outputs stay in its own context. There is no documented size cap on that returned result, and Anthropic's own warning plus closed GitHub issues confirm that many subagents returning long results can push the parent to "Prompt is too long". Background subagents (the default) return a completion notification in a later turn; forks copy the parent's full context and share its prompt cache.

### Cited Findings
- Documented: "The parent doesn't see the subagent's intermediate tool calls or outputs, only that final result." — [Tools reference, Agent tool behavior](https://code.claude.com/docs/en/tools-reference#agent-tool-behavior)
- Documented: a subagent "starts with a fresh, isolated context window" and does not see the parent's history or files read. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented warning: "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own while it runs." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented: the sub-agents page gives no explicit size limit on the returned result (checked the whole page, two reads). — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented: the context-window walkthrough says that after a subagent finishes, "Only the summary and a small metadata trailer come back." — [Explore the context window](https://code.claude.com/docs/en/context-window)
- Documented: Bash tool results are "Inline up to roughly 30,000 characters by default; past that, the path of a file saved to the session directory" plus a 2,000-character preview; this applies to Bash output, not to Agent results. `BASH_MAX_OUTPUT_LENGTH` default 30,000, max 150,000; `bashOutputMaxChars` up to 128,000 (v2.1.261+). — [Tools reference, output limits](https://code.claude.com/docs/en/tools-reference)
- Documented: hook text (additionalContext etc.) over 10,000 characters is saved to a file with a 2,000-character preview. — [Hooks](https://code.claude.com/docs/en/hooks)
- Documented: background is the default. "Subagents spawned from the main conversation start in the background by default"; results arrive "as a completion notification in a later turn"; the Agent tool's response for a background launch is `status: "async_launched"` with no usage fields. — [Subagents](https://code.claude.com/docs/en/sub-agents); [Hooks](https://code.claude.com/docs/en/hooks)
- Documented: background subagents get a smaller built-in tool set than foreground ones (except forks and resumed foreground subagents). — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented: while fork mode is on (default from v2.1.302; in interactive terminal from v2.1.232), "Claude also can't wait for a subagent" in interactive terminal, VS Code or desktop sessions; set `CLAUDE_CODE_FORK_SUBAGENT=0` to let it wait. — [Subagents, fork mode](https://code.claude.com/docs/en/sub-agents#turn-fork-mode-off)
- Documented: a fork "inherits the entire conversation so far instead of starting fresh"; "only its final result comes back"; it shares the parent's prompt cache, so "a fork costs less than a fresh subagent"; a fork can't spawn further forks. — [Subagents, fork](https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation)
- Documented: `maxTurns` caps a subagent; at the limit the result is "marked as partial" and Claude can resume it. — [Tools reference](https://code.claude.com/docs/en/tools-reference#agent-tool-behavior)
- Documented: concurrent subagent limit is 20 by default; past it the Agent tool fails with `Concurrent subagent limit reached`; `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (v2.1.217+) changes it; nesting depth default 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`); "There's no limit on the total number of subagents Claude can spawn over a session." — [Subagents](https://code.claude.com/docs/en/sub-agents); [Env vars](https://code.claude.com/docs/en/env-vars)
- Documented: subagents auto-compact on their own context; `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` applies to subagents; `autoCompactWindow` frontmatter (100k–1M tokens, v2.1.296+) compacts one subagent earlier; a subagent's window "is sized by its own model, not the parent's". — [Subagents, auto-compaction](https://code.claude.com/docs/en/sub-agents)
- Documented: subagent transcripts live at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`; main-conversation compaction does not touch them. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented: in auto mode (v2.1.271+), the final report goes through the `SubagentHandback` tool and "the classifier reviews the report before it's delivered". — [Tools reference](https://code.claude.com/docs/en/tools-reference)
- Reported (GitHub #23463, opened 2026-02-05, closed "not planned" by stale bot 2026-04-17, v2.1.32): seven parallel Task subagents returned 15K–37K characters each (~150K total); the parent then answered "Prompt is too long" to every message, including the subsequent agent notifications, and the session was unrecoverable. No maintainer response; 12 comments; commenters hit it with 3–5 agents too. Linked feature request #27483 asks for a size limit on task returns. — [Issue #23463 mirror](https://claudeissues.com/issue/23463-subagent-results-silently-overflow-context-causing-unrecoverable-session-crash)
- Reported (GitHub #86200, opened 2026-08-12, closed "not planned" by stale bot 2026-10-13, Linux): a background Agent-tool subagent "wedged" with zero assistant turns for ~13 minutes and never recovered; a follow-up SendMessage was never delivered; a comment on v2.1.218 counted 31 of 188 task notifications dropped from the queue, 11 of them from successfully completed subagents. No maintainer response. — [Issue #86200](https://github.com/anthropics/claude-code/issues/86200)
- Reported (GitHub #41208, Desktop app 2.1.87, closed 2026-05-04 per mirror): Explore/Plan subagents failed with "Prompt is too long" even for trivial prompts; related mirrors blame a large deferred MCP tool list or the subagent's fixed system-prompt overhead (one mirror: claude-code-guide ~214K tokens). — [Issue #41208](https://github.com/anthropics/claude-code/issues/41208); [mirror #84947](https://claudeissues.com/issue/84947-claude-code-guide-subagent-cannot-be-invoked-fixed-214k-token-overhead-exceeds-t)
- Third-party, consistent with docs: a subagent's result "sits in your context for the rest of the session" and is reprocessed on every later turn. — [Zivtech, Economics of Claude Code pt. 2](https://www.zivtech.com/blog/economics-of-claude-code-part-2-agent-tradeoff)

### Inferences
- The returned result is injected into the parent as an ordinary tool result and is not truncated or spilled to a file the way Bash output is. Therefore the only guards on parent growth are (a) the subagent's own brevity, (b) the parent's auto-compaction, and (c) you asking workers to write to files and return a path.
- Because the default is background + "Claude can't wait" in fork mode, a parent that spawns N workers ends its turn, then receives N completion notifications in later turns. Each notification turn re-sends the whole parent context (see Q3), so cost grows roughly as N × context size, and lost notifications (reported, not acknowledged by Anthropic) look like a stall.
- The 20-concurrent cap is a client-side limit on spawns, not a request-rate limiter; it does not protect against 429/529 (see Q4, Q6).

### Gaps
- No official statement of a maximum size for an Agent-tool result or what happens when one exceeds remaining context; only the reported behaviour (#23463) exists.
- No documentation of the notification-delivery mechanism that #86200 describes as lossy.

## Q2. Agent teams, Workflows (agent()/parallel()/pipeline()), ultracode

### Takeaway
Dynamic workflows are the documented answer to fan-out stalls: a JavaScript script holds the loop and the intermediate results, so "Claude's context holds only the final answer"; it has a 16-agent default concurrency cap, JSON-schema results, stall detection with automatic restarts, and pauses on usage limits. Agent teams are the opposite trade: experimental, each teammate a full session, ~7x tokens.

### Cited Findings
- Documented: "A workflow script holds the loop, the branching, and the intermediate results itself, so Claude's context holds only the final answer." — [Workflows](https://code.claude.com/docs/en/workflows)
- Documented comparison table: subagents keep intermediate results in "Claude's context window"; workflows keep them in "Script variables"; scale "Dozens to hundreds of agents per run"; interruption "Resumable in the same session". — [Workflows](https://code.claude.com/docs/en/workflows)
- Documented API: `agent()` spawns one subagent, `pipeline()` runs one per item, `parallel()` runs a set and waits; plus `phase()`, `log()`, `args`. `agent()` resolves to `null` if stopped or on an unrecoverable API error. — [Workflows](https://code.claude.com/docs/en/workflows#what-the-saved-script-looks-like)
- Documented: `schema` on `agent()` makes it "return JSON matching the shape instead of prose"; schema checked before start; after five failed validations the call fails (`MAX_STRUCTURED_OUTPUT_RETRIES`). — [Workflows](https://code.claude.com/docs/en/workflows)
- Documented limits: "Up to 16 concurrent agents by default, fewer when Claude Code has fewer CPUs available"; `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1–256 (v2.1.269+); 4,096 items per `parallel()`/`pipeline()`; 1,000 agents per run; no mid-run user input; no `import()`. — [Workflows, behavior and limits](https://code.claude.com/docs/en/workflows#behavior-and-limits)
- Documented stall handling: "An agent whose output stops arriving for long enough starts over from the same prompt"; up to five restarts; errors `agent stalled on all 6 attempts` / `agent lost its reply on all 6 attempts`; `stallMs` per call or `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`, "which also applies to subagents outside workflows"; `CLAUDE_STREAM_IDLE_TIMEOUT_MS` governs the streaming watchdog. — [Workflows, stalls](https://code.claude.com/docs/en/workflows#when-an-agent-stalls-and-restarts)
- Documented usage-limit behaviour: on a claude.ai subscription an agent that hits the usage limit pauses the run and resumes after reset (v2.1.271+), only in interactive sessions with `autoContinueAtUsageLimit` on, reset within 24 h, and at most two waits per run. — [Workflows](https://code.claude.com/docs/en/workflows#when-a-run-hits-your-usage-limit)
- Documented cost warnings: `Large workflow` warning when a run schedules more than 25 agents or projects over 1.5 million tokens; `workflowSizeGuideline` small/medium/large (<5/<10/<50 agents), default medium. — [Workflows, cost](https://code.claude.com/docs/en/workflows#cost)
- Documented: ultracode (`/effort ultracode`, keyword `ultracode`) makes Claude plan a workflow for every substantive task; "each request uses more tokens and takes longer"; with ultracode on, the concurrent subagent limit "isn't enforced" and the Large workflow warning is suppressed. — [Workflows](https://code.claude.com/docs/en/workflows#let-claude-decide-with-ultracode)
- Documented fan-out caching: same-prefix agents are held up to `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS` (5000 ms default) so they read the first agent's cached prefix. — [Workflows](https://code.claude.com/docs/en/workflows#prompt-caching-in-a-fan-out)
- Documented resumption: a run does not continue after you exit; relaunch replays saved results; a failed agent re-runs along with every agent after it. — [Workflows](https://code.claude.com/docs/en/workflows#resume-after-a-pause)
- Documented: available on all paid plans; on Pro it is off until enabled in `/config`; `/deep-research` is a bundled workflow. — [Workflows](https://code.claude.com/docs/en/workflows)
- Documented: Agent teams "are experimental and disabled by default" (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`); "There's no hard limit on the number of teammates"; start with 3–5; "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode"; no background subagents from in-process teammates; no session resumption of in-process teammates. — [Agent teams](https://code.claude.com/docs/en/agent-teams); [Costs](https://code.claude.com/docs/en/costs#agent-team-token-costs)
- Documented: enabling teams changes ordinary delegation: "a subagent that Claude names launches as a teammate, so teams can form even when you didn't ask". — [Agent teams](https://code.claude.com/docs/en/agent-teams#enable-agent-teams)
- Reported (GitHub #24253, Feb 2026, mirror only): "Agent teams hang claude code". Status not verified. — [mirror](https://claudeissues.com/issue/24253-bug-agent-teams-hang-claude-code)

### Inferences
- For a research-style fan-out the documented design intent is workflows, not Agent-tool orchestration: results live outside the model context, and the runtime (not the model) handles concurrency, stalls and usage-limit pauses.
- The 16-agent workflow cap is lower than the 20-subagent cap and is CPU-aware; a workflow therefore self-throttles where an Agent-tool loop does not.

### Gaps
- The docs do not state the default stall window length (only how to lengthen it).
- No official data on how many concurrent API requests the server tolerates per subscription account (see Q4).

## Q3. Context-window management: compaction, /clear, warnings, 1M, cost and latency per turn

### Takeaway
Documented and explicit: "Claude Code sends your full conversation with every request", and each tool-result batch is another such request; so per-turn cost (and, when the cache is cold, latency) scales with context size. Auto-compaction triggers near the model's window (about 967K on native-1M models, 200K otherwise), `/compact` is itself a large request, `/clear` is free.

### Cited Findings
- Documented: "Claude Code sends your full conversation with every request, and each time Claude uses tools it sends another request carrying that batch of tool results." — [Costs, why usage climbs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session)
- Documented: "a one-line question in a session that has been open all day still draws usage for the whole conversation." — [Costs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session)
- Documented: "Token costs scale with context size: the more context Claude processes, the more tokens you use." — [Costs, reduce token usage](https://code.claude.com/docs/en/costs#reduce-token-usage)
- Documented: "Each time you send a message in Claude Code, it makes a new API request. The model doesn't remember anything between requests, so Claude Code re-sends the full context". — [Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching#how-the-cache-is-organized)
- Documented: "Subagents and workflows: every subagent ... sends its own requests on top of the main conversation's." — [Costs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session)
- Documented: "`/compact` reads the conversation it summarizes, so compacting a large context is itself a large request. When you want a fresh start instead of continuity, `/clear` costs nothing". — [Costs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session)
- Documented: a warm-cache `/compact` "costs a fraction of what the context size suggests"; after a break longer than the TTL it reprocesses the history uncached. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching#compacting-the-conversation)
- Documented thresholds: models with a native 1M window (Fable, Sonnet 5+, Haiku 5.5, Opus 4.7+) "compact before the window fills, at about 967K tokens by default"; models without it compact at 200K; `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` forces 200K. — [Model config, auto-compact thresholds](https://code.claude.com/docs/en/model-config#default-auto-compact-thresholds)
- Documented controls: `/autocompact 500k`, `autoCompactWindow` setting (100K–1M), `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (overrides all), `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (can only lower the trigger). — [Model config](https://code.claude.com/docs/en/model-config#set-the-auto-compact-window); [Env vars](https://code.claude.com/docs/en/env-vars)
- Documented: "A context or auto-compact warning: not a usage limit"; it means the conversation is close to the auto-compact window. — [Costs](https://code.claude.com/docs/en/costs#when-a-developer-asks-about-a-limit)
- Documented: after compaction Claude Code re-reads up to five recently modified files (files over 5,000 tokens come back as a path only), re-injects CLAUDE.md, memory, skill descriptions (v2.1.304+), and background subagents "Keep running". — [Context window](https://code.claude.com/docs/en/context-window#what-survives-compaction)
- Documented: idle compaction can run on a long conversation left idle on the one-hour TTL; `idleCompaction: false` disables it (v2.1.290+). — [Prompt caching](https://code.claude.com/docs/en/prompt-caching#compacting-the-conversation)
- Documented 1M availability: Opus 4.6 and Sonnet 4.6 need `[1m]`; Opus 4.6 1M is "Included with subscription" on Max/Team/Enterprise, Sonnet 4.6 1M needs usage credits; newer models run 1M "with no `[1m]` suffix needed". On the API no premium above 200K except Haiku 5.5 above 100K. — [Model config, extended context](https://code.claude.com/docs/en/model-config)
- Documented: `/context` gives a live per-category breakdown; `/usage` shows the session's cache stats and attribution of usage to subagents (v2.1.251+). — [Costs](https://code.claude.com/docs/en/costs#track-your-costs)
- Documented: "Delegate verbose operations to subagents ... only a summary returns to your main conversation." — [Costs](https://code.claude.com/docs/en/costs#delegate-verbose-operations-to-subagents)
- Documented (support): "Each turn resends the conversation so far", project context, and the new prompt; "The conversation history grows fastest." — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)

### Inferences
- A parent at, say, 300K tokens that receives 30 background completions pays 30 × 300K input tokens; with a warm cache this is mostly cache reads (cheap, and not counted toward API ITPM, see Q5), but on a subscription it still "draws usage for the whole conversation" each time.
- Latency per turn is dominated by uncached prefix processing after a cache miss; a parent that idles past the TTL waiting for workers pays that on its next turn.

### Gaps
- No official numbers for processing latency as a function of context size.
- The exact auto-compact percentage (the default `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` baseline) is not stated in the pages read.

## Q4. Usage limits on Max (5x/20x): windows, how subagents and parallel sessions count, "slow" vs "blocked"

### Takeaway
Documented: Max has a rolling five-hour session limit and a weekly limit shared across claude.ai and all Claude Code surfaces; subagents, workflows, teammates and parallel sessions all draw on the same pool. At the limit requests are blocked until reset (or switch to usage credits), not slowed. The "Server is temporarily limiting requests (not your usage limit)" message is a 529 overload, a separate capacity condition.

### Cited Findings
- Documented (support, from search snippet; full article not read): "Both Pro and Max plans have a five-hour session limit and a weekly limit. All activity in both tools counts against the same limits." — [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)
- Documented (support, snippet): Max 5x is five times Pro's per-session allowance, Max 20x twenty times; the weekly limit "resets at a fixed time assigned to your account", shown under Settings > Usage; the session limit "resets on a rolling five-hour cycle". — [What is a limit reset?](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset); [What is the Max plan?](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)
- Documented (support, snippet): Fable models "draw from your plan's regular weekly usage limits and use them faster than other Claude models", up to half the weekly limit. — [Claude Fable models on your plan](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan)
- Documented (support, snippet): if you hit the session limit mid-response "Claude Code may finish the step in progress"; this wrap-up allowance "is small and capped, and the usage counts toward your weekly limit". — [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)

### Inferences
- "Slow" near a limit is not a documented mode; what users perceive as slowness in a fan-out is retry backoff on 429/529 (up to 10 attempts, 500 ms to 32 s each for 529) across many concurrent workers, not throttled throughput.
- The subscription pool is consumed by total tokens across all concurrent requests; with N workers each re-sending its own growing context, the pool drains N times faster than a single session, which matches the 2026-10-27 observation of hitting the 5-hour window 4x.

### Gaps
- Anthropic publishes no per-session token or request figures for Max 5x/20x, no weekly multiplier, and no concurrent-request ceiling for subscription accounts.
- Whether 429 "Request rejected" on a subscription is a short-window burst limit (token-bucket style, as documented for the API) is not stated for claude.ai accounts.
- I could not open the "About Claude's Max plan usage" article (both URL forms returned 404 on 2026-10-28); findings above come from sibling support articles via search snippets.

## Q5. Prompt caching in Claude Code: automatic, what breaks it, 5-minute vs 1-hour TTL, idle parents

### Takeaway
Caching is automatic and prefix-based; the main conversation on a Max subscription gets a one-hour TTL, but subagents, forks, workflows and compaction get five minutes unless `subagentPromptCacheTtl: 1h` is set. A parent that waits longer than its TTL between turns pays a full uncached re-read; tool-list changes, model/effort switches and compaction also invalidate.

### Cited Findings
- Documented: "Claude Code handles prompt caching for you, unless you disable it." The API matches "the start of each request, called the prefix"; "a change anywhere in the prefix recomputes everything after it. There is no per-file or per-segment caching." — [Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching#how-the-cache-is-organized)
- Documented layer order: system prompt (tool definitions) → project context (CLAUDE.md, memory) → conversation. "A change to the system prompt invalidates everything". — [Prompt caching](https://code.claude.com/docs/en/prompt-caching#how-the-cache-is-organized)
- Documented invalidators: switching models, changing effort (except on Opus/Sonnet/Haiku 5.5 and Fable 5.1 with API key or subscription, v2.1.260+), fast mode toggle, MCP server connect/remove when tools are not deferred, plugin MCP changes, denying an entire tool without tool search, compaction, image batch removal, upgrading Claude Code. — [Prompt caching, actions that invalidate](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache)
- Documented: with tool search (default) "Claude Code keeps the tool list from the conversation's first request for the whole conversation", so mid-session MCP changes don't break the cache. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching#connecting-or-removing-an-mcp-server)
- Documented keep-cache actions: editing files, editing CLAUDE.md (doesn't apply until /clear, /compact or restart), permission mode changes, output style (v2.1.251+), skills/commands, `/recap`, `/rewind`, "Spawning a subagent". — [Prompt caching, actions that keep](https://code.claude.com/docs/en/prompt-caching#actions-that-keep-the-cache)
- Documented TTL: "Cached prefixes expire after a period of inactivity. Each request that hits the cache resets the timer"; "the first turn back after stepping away can be noticeably slower." — [Prompt caching, cache lifetime](https://code.claude.com/docs/en/prompt-caching#cache-lifetime)
- Documented TTL buckets: on a Claude subscription within plan usage the main conversation gets one hour; "Everything else" (subagents, workflows, in-process teammates, forks, compaction, session titles) gets five minutes; on usage credits / API key both get five minutes. Settings `promptCacheTtl` and `subagentPromptCacheTtl` (`5m`/`1h`, v2.1.242+); env `CLAUDE_CODE_PROMPT_CACHE_TTL`, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`; `FORCE_PROMPT_CACHING_5M=1`, `ENABLE_PROMPT_CACHING_1H=1`. 1-hour writes bill at a higher rate. — [Prompt caching, which TTL](https://code.claude.com/docs/en/prompt-caching#which-ttl-each-request-gets)
- Documented: a subagent's "first request doesn't read the parent's cache, because the two prefixes differ"; "The parent's cache is unaffected"; a fork "reads the parent's cache"; a resumed subagent can read the cache its original run warmed. — [Prompt caching, subagents](https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache)
- Documented: "Cache misses: your first message after a break longer than the cache lifetime misses the cache and reprocesses your full context." — [Costs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session)
- Documented: cache is "effectively scoped to one machine and directory"; parallel sessions in the same directory "can read each other's cache"; API cache isolated per organization and sometimes per workspace. — [Prompt caching, cache scope](https://code.claude.com/docs/en/prompt-caching#cache-scope)
- Documented: `/usage` shows a `Prompt cache (main)` line with hit share, misses, "expected rebuild (compaction or tool-result clearing)", and warm/cold with TTL (v2.1.251+; likely-cause text v2.1.260+). — [Costs](https://code.claude.com/docs/en/costs#prompt-cache-statistics)
- Documented (API): "only uncached input tokens count toward your ITPM rate limits" for most models; `cache_read_input_tokens` do not count; `input_tokens` + `cache_creation_input_tokens` do. Example: 2M ITPM with 80% hit rate ≈ 10M total input/min. — [API rate limits](https://platform.claude.com/docs/en/api/rate-limits#cache-aware-itpm)
- Documented (API): a 429 may carry `retry-after`; "You might hit rate limits over shorter time intervals" (e.g., 60 RPM enforced as 1 per second); acceleration limits trigger on sharp usage increases; token-bucket replenishment. — [API rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- Reported (mirror #57751): "Subagents inherit parent prompt cache (~150K tokens), causing plan-mode bleed"; this describes fork-style inheritance, consistent with documented fork behaviour. Status not verified. — [mirror](https://claudeissues.com/issue/57751-subagents-inherit-parent-prompt-cache-150k-tokens-causing-plan-mode-bleed-self-p)

### Inferences
- In a fan-out the parent's one-hour TTL is usually safe, but the workers' five-minute TTL is not: a worker that blocks on a slow tool call for more than five minutes re-reads its own context uncached on its next request. `subagentPromptCacheTtl: 1h` is the documented fix, at higher cache-write cost.
- Because cache reads don't count toward API ITPM, the "many workers, same prefix" pattern is far cheaper for rate limits on the API than on a subscription pool, where the docs say cached re-reads still "draw usage".

### Gaps
- The docs do not say whether cache-read tokens are discounted in the subscription usage meter the way they are in API billing; the costs page only says the re-read is billed "at the cached token rate" and still draws usage.

## Q7. Settings and features that help: output caps, worker models, max turns, hooks, files, Explore

### Takeaway
The documented levers are: cheaper worker models (`model: haiku`, `CLAUDE_CODE_SUBAGENT_MODEL` + `_FORCE`), `maxTurns`, the read-only `Explore` agent (no CLAUDE.md or git snapshot, no Write/Edit), PostToolUse `updatedToolOutput` to shrink results before Claude sees them, SubagentStop to force a worker to keep going, a 1-hour subagent cache TTL, lower auto-compact windows per subagent, and workflows for anything beyond a handful of workers.

### Cited Findings
- Documented: `CLAUDE_CODE_MAX_OUTPUT_TOKENS` sets max output tokens per request; default 32,000 and cap 128,000 for unrecognized IDs; "Higher values reduce the context available before auto-compaction." — [Env vars](https://code.claude.com/docs/en/env-vars)
- Documented: `MAX_THINKING_TOKENS` sets a fixed thinking budget where adaptive reasoning is off; adaptive-reasoning models ignore it, use `/effort` instead; thinking cannot be turned off on Opus/Sonnet/Haiku 5.5 or Fable. — [Costs](https://code.claude.com/docs/en/costs#adjust-extended-thinking)
- Documented model selection order: per-call `model` alias → frontmatter `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → main model; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` makes the env var win; "specify `model: haiku`" for simple subagent tasks; Explore uses the main model by default, claude-code-guide uses Haiku. — [Subagents](https://code.claude.com/docs/en/sub-agents); [Model config](https://code.claude.com/docs/en/model-config#environment-variables)
- Documented: `maxTurns` frontmatter; partial result + resume. — [Tools reference](https://code.claude.com/docs/en/tools-reference#agent-tool-behavior)
- Documented: Explore is "a fast, read-only agent"; Write/Edit denied; thoroughness "quick", "medium", "very thorough"; "Explore and Plan start without your CLAUDE.md files and the git status snapshot to keep research fast and inexpensive"; one-shot, no agent ID, cannot be resumed. (The in-product description "reads excerpts rather than whole files" is in the agent list, not the docs page.) — [Subagents, Explore](https://code.claude.com/docs/en/sub-agents)
- Documented hooks: `SubagentStop` input includes `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`; `decision: "block"` with `reason` "keeps the subagent running and delivers reason to the subagent as its next instruction"; "To inject context into the parent session after a subagent returns, use a PostToolUse hook on the Agent tool instead." — [Hooks](https://code.claude.com/docs/en/hooks)
- Documented: PostToolUse `updatedToolOutput` "Replaces the tool's output with the provided value before it is sent to Claude. The value must match the tool's output shape"; a mismatched value is ignored for built-in tools. The Agent tool's `tool_response` carries `status`, `agentId`, `content`, `totalTokens`. — [Hooks](https://code.claude.com/docs/en/hooks)
- Documented: hooks "can preprocess data before Claude sees it", e.g. grep ERROR from a 10,000-line log, "reducing context from tens of thousands of tokens to hundreds"; example PreToolUse filter that rewrites test commands with `updatedInput`. — [Costs, offload to hooks](https://code.claude.com/docs/en/costs#offload-processing-to-hooks-and-skills)
- Documented: `SubagentHandback` in auto mode delivers the final report; read it via a PreToolUse/PostToolUse hook on `SubagentHandback` (`tool_input.message`). — [Hooks](https://code.claude.com/docs/en/hooks)
- Documented: `subagentPromptCacheTtl: "1h"` keeps worker caches an hour (v2.1.242+). — [Prompt caching](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself)
- Documented: `autoCompactWindow` frontmatter per subagent (v2.1.296+), `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` applies to subagents. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Documented: `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20), `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3; 1 disables nesting), `CLAUDE_CODE_FORK_SUBAGENT=0` (lets Claude wait), `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` (removes `run_in_background` and auto-backgrounding). — [Env vars](https://code.claude.com/docs/en/env-vars)
- Documented: `CLAUDE_CODE_MAX_RETRIES` (default 10, cap 15 from v2.1.186), `CLAUDE_CODE_RETRY_WATCHDOG`, `API_TIMEOUT_MS` (default 600,000 ms; desktop app sets 900,000 for local sessions), `CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS` / `_MAX_DELAY_MS`. — [Env vars](https://code.claude.com/docs/en/env-vars); [Desktop app](https://code.claude.com/docs/en/desktop); [Errors](https://code.claude.com/docs/en/errors)
- Documented: `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` holds sessions to 200K; `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` for gateways that reject >200K. — [Model config](https://code.claude.com/docs/en/model-config)
- Documented: `/usage` recommendations and the `f` fix shortcut (v2.1.305+) apply `/effort` changes and prompt Claude to trim CLAUDE.md etc. — [Costs](https://code.claude.com/docs/en/costs#apply-recommendations-with-the-fix-shortcut)
- Documented: in Claude Code, writing results to files is the workflow runtime's model ("Agents read, write, and run commands. The script coordinates the agents"); for Agent-tool workers it is only user guidance (closed issue #23463 suggested "write full results to a file, giving the parent a summary and file path"). — [Workflows](https://code.claude.com/docs/en/workflows#behavior-and-limits); [mirror #23463](https://claudeissues.com/issue/23463-subagent-results-silently-overflow-context-causing-unrecoverable-session-crash)
- Documented (desktop): the Background tasks pane "shows the background work running inside the current session: subagents, background shell commands, and dynamic workflows"; desktop reads the same settings files as the CLI; workflow approvals appear as a card with Once/Always/Deny. — [Desktop app](https://code.claude.com/docs/en/desktop); [Workflows](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs)
- Documented: keep CLAUDE.md under ~200 lines; move workflow-specific instructions to skills, which load on demand. — [Costs](https://code.claude.com/docs/en/costs#move-instructions-from-claude-md-to-skills)

### Inferences
- A PostToolUse hook matched on `Agent` that rewrites `content` to a short summary plus a file path is the only documented mechanism that can bound what a subagent result injects into the parent; the docs do not confirm `updatedToolOutput` works on Agent results, so it needs a test.
- For the home-lab use here, the lowest-risk stack is: Haiku/Sonnet workers via frontmatter, `maxTurns`, workers told to write to a file and return a one-paragraph summary, `subagentPromptCacheTtl: 1h`, fan-out waves of well under 20, and workflows (`/deep-research` or a saved script) for anything larger.

### Gaps
- No documented confirmation that PostToolUse `updatedToolOutput` applies to the Agent tool result shape.
- No documented default for the subagent stall window or for how long a dropped background notification is retried.
